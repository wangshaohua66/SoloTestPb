# 文物修复记录系统 - 系统设计文档

## 1. 系统概述

### 1.1 项目背景

文物修复是文化遗产保护的重要环节。传统的修复记录方式存在以下问题：
- 纸质档案易损坏、不易保存
- 信息检索困难，追溯历史记录不便
- 缺乏标准化的数据管理
- 影像资料管理分散

本系统旨在解决上述问题，提供数字化的文物修复档案管理平台。

### 1.2 系统目标

- 实现文物基本信息的标准化录入和管理
- 记录完整的修复过程，支持历史追溯
- 统一管理修复影像资料
- 记录修复材料使用情况
- 支持修复档案的导出和归档
- 提供直观易用的用户界面

### 1.3 功能需求

| 功能模块 | 功能描述 |
|---------|---------|
| 文物档案 | 录入文物基本信息：名称、年代、类别、尺寸、材质、保存状态、病害描述 |
| 修复计划 | 制定修复方案：修复目标、方法、材料、预计工期 |
| 过程记录 | 按时间顺序记录修复过程：操作步骤、使用材料、工具设备、遇到问题 |
| 影像管理 | 记录修复前、中、后的影像资料，支持文件上传 |
| 材料管理 | 记录修复使用材料：名称、来源、用量 |
| 档案导出 | 生成完整的修复档案报告，支持文本格式导出 |

## 4. API接口设计

### 4.1 接口规范

- 协议：HTTP
- 数据格式：JSON
- 编码：UTF-8
- 响应格式：
  ```json
  {
    "code": 200,
    "message": "操作成功",
    "data": {}
  }
  ```

### 4.2 接口列表

#### 文物档案接口

| 方法 | 路径 | 说明 |
|-----|-----|-----|
| GET | /api/artifacts/ | 获取文物列表（分页、搜索） |
| GET | /api/artifacts/:id | 获取文物详情 |
| POST | /api/artifacts/ | 新建文物 |
| PUT | /api/artifacts/:id | 更新文物 |
| DELETE | /api/artifacts/:id | 删除文物 |

#### 修复计划接口

| 方法 | 路径 | 说明 |
|-----|-----|-----|
| GET | /api/plans/?artifact_id=:id | 获取文物的修复计划 |
| POST | /api/plans/ | 新建修复计划 |
| PUT | /api/plans/:id | 更新修复计划 |
| DELETE | /api/plans/:id | 删除修复计划 |

#### 过程记录接口

| 方法 | 路径 | 说明 |
|-----|-----|-----|
| GET | /api/processes/?artifact_id=:id | 获取文物的过程记录 |
| POST | /api/processes/ | 新建过程记录 |
| PUT | /api/processes/:id | 更新过程记录 |
| DELETE | /api/processes/:id | 删除过程记录 |

#### 影像管理接口

| 方法 | 路径 | 说明 |
|-----|-----|-----|
| GET | /api/images/?artifact_id=:id | 获取文物的影像列表 |
| POST | /api/images/ | 新建影像（multipart/form-data） |
| PUT | /api/images/:id | 更新影像信息 |
| DELETE | /api/images/:id | 删除影像 |

#### 材料管理接口

| 方法 | 路径 | 说明 |
|-----|-----|-----|
| GET | /api/materials/?artifact_id=:id | 获取文物的材料列表 |
| POST | /api/materials/ | 新建材料记录 |
| PUT | /api/materials/:id | 更新材料记录 |
| DELETE | /api/materials/:id | 删除材料记录 |

#### 档案导出接口

| 方法 | 路径 | 说明 |
|-----|-----|-----|
| GET | /api/export/list | 获取可导出文物列表 |
| GET | /api/export/artifact/:id | 导出修复报告（文本文件下载） |

## 6. 日志设计

### 6.1 日志配置

- 日志级别：INFO
- 输出位置：控制台 + 文件
- 文件命名：`app_YYYYMMDD.log`
- 日志格式：`时间 - 模块名 - 级别 - 消息`

### 6.2 日志内容

- 系统启动/初始化日志
- API请求日志
- 数据库操作日志
- 错误异常日志

## 7. 安全性设计

### 7.1 输入验证
- 后端对所有输入参数进行验证
- 必填字段校验
- 数据类型校验

### 7.2 文件上传安全
- 限制允许上传的文件类型（图片格式）
- 限制文件大小（最大16MB）
- 使用随机文件名防止路径遍历

### 7.3 错误处理
- 统一的错误响应格式
- 详细的错误日志
- 不向客户端暴露敏感错误信息

## 8. 部署说明

### 8.1 开发环境

1. 安装 Python 3.13
2. 安装 Node.js (>= 16)
3. 分别启动后端和前端开发服务器

### 8.2 生产环境

1. 后端：使用 Gunicorn 等 WSGI 服务器
2. 前端：构建静态资源后使用 Nginx 部署
3. 配置反向代理处理跨域问题
