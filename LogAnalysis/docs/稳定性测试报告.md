## 四、问题记录与修复

### 已修复问题

1. **NetworkLogCollector app context 问题**
   - 问题描述：后台线程保存日志时缺少 Flask app context
   - 解决方案：通过 `collector_manager.set_app(app)` 传递 app 实例
   - 修复文件：`backend/app/modules/log_collector.py`
   - 验证：TCP/UDP 日志成功入库
   - 状态：✅ 已修复并验证

2. **alert_engine 规则匹配字段问题**
   - 问题描述：
     - `_check_error_rate` 使用 `rate_threshold` 但规则配置使用 `threshold`
     - `_check_custom_query` 使用 `keyword` 但规则配置使用 `query`
     - `min_total_logs` 默认值 100 过高，不便于测试
   - 解决方案：
     - 同时支持两种字段名
     - 降低 `min_total_logs` 默认值为 5
   - 修复文件：`backend/app/modules/alert_engine.py`
   - 验证：4种告警规则全部触发
   - 状态：✅ 已修复并验证

### 深入排查发现

**error_rate 规则时间戳问题排查**:
- 检查 `log_routes.py`：使用 `datetime.utcnow()` 保存日志时间戳
- 检查 `alert_engine.py`：使用 `datetime.utcnow()` 计算时间窗口
- 检查 `stats_routes.py`：使用 `datetime.utcnow()` 作为结束时间
- 结论：三者统一使用 UTC 时间，无时间差问题
- 实际触发：错误率 40% > 5% 阈值，成功触发
