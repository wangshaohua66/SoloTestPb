# 日志聚合分析平台 - 使用说明

## 一、环境准备

### 1.1 软件要求

- Python 3.13+
- Node.js 18+
- npm 或 yarn

### 1.2 依赖安装

#### 后端依赖

```bash
cd backend
pip install -r requirements.txt
```

#### 前端依赖

```bash
cd frontend
npm install
```

## 二、系统启动

### 2.1 启动后端服务

```bash
cd backend
python run.py
```

后端服务将在 `http://localhost:5001` 启动。

### 2.2 启动前端服务

```bash
cd frontend
npm run dev
```

前端服务将在 `http://localhost:8001` 启动。

### 2.3 访问系统

打开浏览器访问：`http://localhost:8001`

## 三、功能使用指南

### 3.1 仪表盘

仪表盘展示系统概览数据：

- **总日志数**: 统计收集到的日志总数
- **错误数**: ERROR级别的日志数量
- **警告数**: WARNING级别的日志数量
- **错误率**: 错误日志占比

图表展示：
- 日志趋势图：按时间展示日志数量变化
- 错误率趋势图：展示错误率变化
- 级别分布图：各日志级别占比

### 3.2 日志浏览

查看已收集的日志列表，支持：

- 按日志级别过滤（DEBUG/INFO/WARNING/ERROR/FATAL）
- 按服务名称过滤
- 分页浏览
- 显示日志详情（时间、级别、模块、消息、原始日志）

### 3.3 日志检索

支持多条件组合搜索：

- **关键词搜索**: 在日志消息中搜索关键词
- **时间范围**: 指定开始和结束时间
- **日志级别**: 选择要搜索的级别
- **服务名称**: 按服务过滤
- **模块名称**: 按模块过滤

搜索结果支持分页查看。

### 3.4 统计分析

多维度日志统计：

- **级别分布**: 各日志级别的数量统计（柱状图）
- **服务分布**: 各服务的日志数量（饼图）
- **模块排行**: 日志最多的模块TOP列表
- **时间趋势**: 按时间窗口的日志数量趋势

### 3.5 告警管理

#### 告警列表

展示所有触发的告警，可执行：

- **确认告警**: 标记告警已确认
- **解决告警**: 标记告警已解决

告警状态：
- 未确认：新产生的告警
- 已确认：运维人员已看到
- 已解决：问题已处理

#### 告警规则

创建和管理告警规则：

**支持的条件类型：**

1. **关键词匹配 (keyword)**
   - 检测日志中是否包含指定关键词
   - 配置示例：`{"keywords": ["error", "exception"], "time_window_minutes": 5, "threshold": 5}`
   - 含义：5分钟内出现5次以上error或exception则触发告警

2. **级别阈值 (level_threshold)**
   - 检测特定级别日志数量
   - 配置示例：`{"level": "ERROR", "time_window_minutes": 10, "threshold": 10}`
   - 含义：10分钟内出现10条以上ERROR日志则触发

3. **错误率 (error_rate)**
   - 检测错误日志占比
   - 配置示例：`{"threshold": 5.0, "time_window_minutes": 5}`
   - 含义：5分钟内错误率超过5%则触发

4. **自定义查询 (custom_query)**
   - 使用自定义条件查询
   - 配置示例：`{"query": "数据库连接超时", "time_window_minutes": 1, "threshold": 3}`

### 3.6 报表导出

生成和导出日志分析报表：

**报表类型：**
- **汇总报表**: 统计概览数据
- **详细报表**: 包含汇总和详细日志列表
- **日报**: 当日统计数据
- **周报**: 一周统计数据

**导出格式：**
- **JSON格式**: 结构化数据，适合程序处理
- **文本格式**: 易读格式，适合人工查看

**操作步骤：**
1. 选择报表类型
2. 选择导出格式
3. 可选：指定时间范围和服务
4. 点击"预览报表"查看内容
5. 点击"下载报表"保存文件

### 3.7 配置管理

#### 日志来源配置

配置日志收集来源：

**来源类型：**

1. **文件来源**
   - 配置文件路径
   - 系统实时监听文件新增内容
   - 支持关联服务名称

2. **网络端口来源**
   - 配置监听端口
   - 选择协议（TCP/UDP）
   - 外部应用可通过网络发送日志

3. **API来源**
   - 通过HTTP API接收日志
   - 调用 `POST /api/logs` 接口

**操作说明：**
- 点击"新增来源"创建新配置
- 切换开关启用/禁用来源
- 点击"查看配置"查看详情

#### 解析规则管理

管理日志解析规则：

**规则配置：**
- 规则名称：便于识别
- 正则表达式：使用命名捕获组提取字段
- 格式描述：说明适用的日志格式
- 优先级：数值越小优先级越高

**命名捕获组示例：**
```
(?P<timestamp>\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}) - (?P<level>\w+) - (?P<module>\w+) - (?P<message>.*)
```

支持的字段名：
- `timestamp`: 时间戳
- `level`: 日志级别
- `module`: 模块名
- `message`: 消息内容
- 其他自定义字段

#### 解析测试

测试日志解析效果：

1. 在"日志内容"输入要测试的日志行
2. 可选：在"自定义正则"输入测试正则
3. 点击"测试解析"查看结果
4. 系统显示：
   - 检测到的格式类型
   - 解析出的各字段值

## 四、API接口使用

### 4.1 日志接入

#### 单条日志接入

```bash
curl -X POST http://localhost:5001/api/logs \
  -H "Content-Type: application/json" \
  -d '{
    "timestamp": "2026-01-15T08:30:15",
    "level": "INFO",
    "module": "app",
    "message": "用户登录成功",
    "service_name": "user-service"
  }'
```

#### 批量日志接入

```bash
curl -X POST http://localhost:5001/api/logs/batch \
  -H "Content-Type: application/json" \
  -d '{
    "logs": [
      {
        "timestamp": "2026-01-15T08:30:15",
        "level": "INFO",
        "message": "日志1"
      },
      {
        "timestamp": "2026-01-15T08:30:16",
        "level": "ERROR",
        "message": "日志2"
      }
    ]
  }'
```

#### 原始日志接入（自动解析）

```bash
curl -X POST http://localhost:5001/api/logs \
  -H "Content-Type: application/json" \
  -d '{
    "raw_log": "2026-01-15 08:30:15,123 - INFO - main - 应用启动",
    "service_name": "my-service"
  }'
```

### 4.2 日志查询

#### 搜索日志

```bash
curl -X POST http://localhost:5001/api/search \
  -H "Content-Type: application/json" \
  -d '{
    "keyword": "error",
    "level": "ERROR",
    "start_time": "2026-01-15T00:00:00",
    "end_time": "2026-01-15T23:59:59",
    "page": 1,
    "page_size": 50
  }'
```

#### 获取统计概览

```bash
curl "http://localhost:5001/api/stats/overview?time_window_minutes=60"
```

## 六、常见问题

### Q1: 后端启动失败，提示端口被占用？

A: 检查5001端口是否被其他程序占用，或修改 `backend/config.py` 中的 `BACKEND_PORT`。

### Q2: 前端无法连接后端？

A: 确认后端服务已启动，检查 `frontend/vite.config.js` 中的代理配置是否正确。

### Q3: 日志解析不正确？

A: 
1. 在"配置管理"→"解析测试"中测试日志行
2. 检查是否匹配内置格式
3. 添加自定义解析规则

### Q4: 如何导入现有日志文件？

A:
1. 方式一：在"配置管理"→"日志来源"中添加文件来源
2. 方式二：通过API批量导入

### Q5: 数据库文件在哪里？

A: SQLite数据库位于 `backend/data/log_analysis.db`，可删除该文件重置所有数据。
